# 可用的选点与天气规划

用户要求修复始终无结果的规划界面并增加真实场所。根因是 RuleBasedPlanner 写死 eligible=false、忽略距离/需求；界面把全部未知场所逐条显示为不推荐。

1. 扩充具名称、地址、地图来源和查询时间的重庆钓场数据；地图收录只证明 POI，不作为开放许可。无官方或经营方现行证据的记录保持 UNKNOWN。
2. 把候选探索与正式推荐分开：按直线距离、半径和有证据的需求过滤，未知鱼种标注待确认；禁止/DEMO 不混入真实候选。无半径内记录时给扩大范围操作，不暗中忽略半径。未知坐标单独计数。
3. 正式推荐使用真实安全闸门与匹配条件，移除硬编码 false；仍不生成未经校准的评分。未核实许可不获得推荐资格。
4. 对话中展示简短摘要、最多几个候选卡片和下一步操作；选定场所后单独请求该坐标的真实天气，给出覆盖范围内风雨较小的连续两小时窗口，缺失、过期或风险天气明确阻断。取消/切换选择不串数据。
5. 使用单元测试验证范围、需求过滤、正式资格正反路径、时段缺失/风险/连续性。浏览器验证候选选择、扩大范围、天气失败重试、手机排版与示例隔离。执行 lint/typecheck/test/build 和真实浏览器检查。

保留静态 React/Vite 架构、既有主题，不接大模型、不配置新密钥、不部署。当前位置参考不是钓场天气，参考地图点不是具体钓位。
