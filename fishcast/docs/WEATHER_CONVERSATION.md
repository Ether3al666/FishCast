# 按问题回答天气与场所

2026-11-17。用户问“先看看明天上午的天气”时，旧实现只提取日期和时段，所有有效请求均渲染 `TripResults`，导致天气问题仍展示场所统计和钓点卡片。

## 调整

- 在现有本地规则上区分天气、风雨时段比较和找场所；没有引入模型 API 或新密钥。
- 天气问题直接呈现该时段的气温、累计降水、最大风速、逐小时预报和来源时间。降雨、风速、气温问题有对应摘要及优先指标；明确找点后才展示场所卡片。
- “那下午呢”“看全天”等追问继承话题。只给日期的天气问题查询全天；普通出钓规划仍要求时间段。
- 已选场所及完整场所名称用于对应坐标查询。区县天气先选择具体场所，不把主城区参考天气冒充整个区县天气。长名称优先于被其包含的短名称；并列场所要求明确一个。
- 从场所天气继续找附近地点，使用所选场所作为距离中心；重新核查保持该位置。新对话和精确设置清除先前的地点上下文。
- 请求完成及刷新后自动更新天气回答；加载、错误、过期、示例、坐标不匹配、缺小时或关键字段缺失不输出正常统计。半小时时段说明整小时累计边界。
- “几点去合适”才比较两小时时段；今日时段只比较尚未开始的整小时。结果不输出鱼获概率或开放许可判断。

## 验证

lint、typecheck、135 项单元测试、34 项浏览器测试及生产构建通过。浏览器测试包含延迟加载、刷新数值变化、失败重试、上午/下午/全天、天气与找点切换、具体地点与区县切换、长短名称、附近距离中心、375px 布局；测试天气响应只在拦截器中使用。

真实 Open-Meteo 浏览器检查成功（无请求拦截）：参考中心明日上午返回 10.5–11.3°C、累计降水 2.5 mm、最大风速 9.4 km/h；问降雨后只重点概括降水，切至下午后累计为 0.0 mm。这些数值只是检查时刻的预报快照，未写入产品数据。问天气时钓点卡片数为 0；页面脚本异常为 0，375px 无横向溢出。
