# 天气不可用排查

2026-11-17，用户内置浏览器在华建沟垂钓中心显示天气获取失败。

## 后续处理：短暂连接失败自动重试

2026-11-17 用户截图中小渔村钓鱼休闲中心显示“无法连接天气接口”。这是 fetch 的网络错误，与等待满 30 秒触发的 TimeoutError 不同。此次检查中，相同接口重新取得完整预报：Edge 应用适配器约 1.2 秒，Node 直连约 0.9 秒，显式使用现有本地代理约 0.7 秒。用户内置浏览器同时已显示千羽垂钓园真实天气，获取时间 14:57。这些证据表明连接存在波动，不能据此确定为某个代理、DNS 或服务端故障。没有修改用户系统代理或添加转发服务。

处理：网络 TypeError 或 HTTP 5xx 在 800 毫秒后自动重试一次；首次请求、等待和重试共用一个 30 秒截止信号。HTTP 429、无效数据、主动取消与超时不重试。切换地点立即取消等待和旧请求。原有真实天气缓存、地点隔离和数据校验继续生效。

验证：先添加失败用例确认原代码只请求一次，再实现重试；60 项单元测试、26 项浏览器用例、lint、typecheck、build 全部通过。新增覆盖包括短暂网络失败恢复、503 恢复、持续失败最多两次、切换地点取消、接近截止时间失败仍不超过 30 秒、429 与无效数据不重试。浏览器验证了首次刷新失败后无需再点击即可恢复，并保留持续失败时的旧缓存标记。

改动后使用应用适配器实查截图中的小渔村：约 0.96 秒返回 Open-Meteo 的 168 小时真实预报，`isDemo=false`。自动重试可缓解短暂故障，并不保证持续断网时能获得数据。

## 后续调整：30 秒等待上限

2026-11-17 按用户要求，将天气请求的 `AbortSignal.timeout` 从 12000 调整为 30000 毫秒，超时提示同步显示“30 秒”。下方的 12 秒记录描述此前排查时的设置。此次调整只延长请求等待时间，不表示网络连接问题已经恢复。

验证：lint、typecheck、55 项单元测试与构建通过；3 项天气相关浏览器用例通过，覆盖请求失败与重试、成功后失败保留缓存、选点查询当地天气。

## 实测

- 当前用户页面重复请求后仍失败。将原有统一 catch 提示分类后，实际显示 TimeoutError 对应的“天气连接超时（12 秒）”。原请求 AbortSignal.timeout(12000) 达到上限，未获得可用返回。
- 本机 Edge 对同一场所、同一计划成功取得真实 Open-Meteo 天气，解析与时段比较通过。不是该场所没有坐标，也未发现该请求需要高德 Key。
- Node 直连 Open-Meteo 失败，底层为 UND_ERR_CONNECT_TIMEOUT。Windows 配有已启用的本地系统代理。现有证据表明联网路径存在差异，不能仅凭此断言内置浏览器具体采用了哪条代理路径。
- 没有修改系统代理、浏览器全局设置或引入第三方天气转发服务。内置浏览器联网问题尚未恢复；可先在实测正常的 Edge 使用同一 localhost URL。

## 本轮改动

- 区分超时、网络、HTTP 429/其他 HTTP 状态、浏览器兼容和响应数据异常；不输出原始 URL 或坐标。
- 同一天气失败只显示一次具体错误，取消重复“当地天气不可用”提示。
- 保持 12 秒超时和原有严格数据校验，不把接口失败归因于钓场许可、不编造天气。
